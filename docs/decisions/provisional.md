## User decisions (2026-10-24, before the M3.5–M6 build)

| # | Decision |
|---|---|
| U-1 | Build M3.5 (discovery and passphrase unlock), then M4, M5 and M6, in roadmap order |
| U-2 | **Accept prompt:** a live-desktop connection asks the person at the screen (Allow/Deny, denied after 30 s) **unless the viewer authenticated as the same OS user account** that runs the agent. Password-only types (VncAuth) carry no username, so they always prompt |
| U-3 | **Wayland:** keep the portal restore token so access is approved once per login; it can be revoked in the agent settings |
| U-4 | **Presence indicator (SRV-12):** tray icon (red while connected, with "Disconnect everyone") plus a desktop notification on each connection |
| U-5 | The agent listens on **loopback by default**; `--listen lan` opts in to network access, which is encrypted-only (ADR-0009 unchanged) |
| U-6 | systemd **user** unit shipped but **not enabled** on install |
| U-7 | A second computer opens in a **new tab** by default; it can be moved to its own window |
| U-8 | (2026-10-24) **Merge each finished milestone to `main`** (fast-forward, which publishes a release with `.deb` files) once it passes the local checks; milestone branches are still pushed too |
| U-9 | **Headless shared input (M7):** one controller at a time. The first viewer controls; others watch until the controller hands over or the owner takes over (the owner always can) |
| U-10 | **Headless session (M7):** runs `~/.config/farsight/headless-startup` (like TigerVNC's xstartup); the default opens a terminal and the file manager; X11 apps through Xwayland |
| U-11 | **Compat names (M9):** an optional `farsight-tigervnc-compat` `.deb` that provides `vncviewer`, `vncserver`, `x0vncserver`, `vncpasswd` and conflicts with the TigerVNC packages |
| U-12 | (2026-10-24) **H.264 (M10):** use Cisco's prebuilt OpenH264 library, downloaded at first use (Cisco covers the patent royalties for that binary); off by default, opt-in |
| U-13 | **GPU paths (M10):** an ADR allows `unsafe` only in one small, reviewed `-sys` crate, behind an optional feature |
| U-14 | **Validation (M10):** GPU/H.264 code is built and unit-tested in CI with software fallbacks, and enabled in release builds only after the user confirms a hand test on their Pop!_OS machine |
| U-15 | (2026-10-25) **Hardware H.264 (M10):** write GPU encoding now, not later: VA-API for AMD (the developer's machine) and NVENC for NVIDIA (the user's other machine), DMA-BUF capture too; the user hand-tests on both |
