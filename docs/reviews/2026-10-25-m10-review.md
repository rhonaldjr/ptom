# M10 review: GPU H.264, DMA-BUF capture, `farsight-gpu-sys` (2026-10-25)

Three personas reviewed M10, as [code-review.md](../process/code-review.md) requires for FFI, `unsafe`, native
libraries and data from the network:

- the Senior Engineer;
- the Security Architect;
- the Ethical Hacker.

None found a blocker. The findings and how each was resolved are below.

| # | Persona | Severity | Finding | Resolution |
|---|---|---|---|---|
| 1 | Ethical Hacker | Major | OpenH264 loading relied on the `openh264` crate's list of known hashes. That list includes older Cisco builds, some with known decoder flaws | Fixed: Farsight's own pinned SHA-256 is checked before every load (`farsight_h264::verify`), with a test |
| 2 | Senior Engineer | Major | DMA-BUFs were allowed for the shared-memory format too, which has no modifier. A tiled buffer would then be read as rows and come out scrambled | Fixed: DMA-BUFs are accepted only when the negotiated format carries the LINEAR modifier (`negotiated_memory`) |
| 3 | Senior Engineer | Major | `DONT_FIXATE` was set without a fixation step | Fixed: dropped. The modifier has a single choice, so it stays mandatory |
| 4 | Ethical Hacker | Minor | A hostile stream could declare a huge picture, which the viewer allocated before checking its size, and could pack many pictures into one rectangle | Fixed: `VideoDecoder::decode` takes the expected size and refuses other sizes before converting; at most 4 pictures per rectangle. Covered by a regression test and the `codec_video` fuzz target |
| 5 | Ethical Hacker | Minor | Viewers could each open an encoder, up to 16, exhausting GPU sessions or CPU | Fixed: at most 4 H.264 streams at once (`LimitedCodecs`); the rest get lossless updates. Re-creating streams on resize is accepted and recorded in the threat model |
| 6 | Security Architect, Ethical Hacker | Minor | The mapped DMA-BUF was exposed as `&[u8]` while the producer could still write to it | Fixed: the bytes are copied out with a raw copy (`copy_mapping`), and ADR-0021 now says so |
| 7 | Security Architect | Minor | The threat model's DMA-BUF row named the wrong control | Fixed: the row now names the sync-before-mmap ordering and the kernel's size check, and a code comment guards the ordering |
| 8 | Security Architect | Minor | The SAFETY note on `Drop for Va` didn't cover a failed `vaInitialize` | Fixed (note corrected) |
| 9 | Security Architect | Minor | Coded-segment sizes reported by the driver were trusted | Fixed: output larger than the coded buffer is refused |
| 10 | Security Architect | Minor | Nothing enforced the rule that only `farsight-gpu-sys` may drop the workspace lints | Fixed: `scripts/check-layers.sh` fails otherwise, and a negative test was run |
| 11 | Senior Engineer | Minor | The PPS was sent inside the Sequence packed header while PICTURE packed headers were also requested | Fixed: the SPS and PPS are now sent as separate Sequence and Picture packed headers. Re-tested on AMD |
| 12 | Senior Engineer | Minor | The reference ping-pong moved forward even when an encode failed | Fixed: it moves forward only on success |
| 13 | Senior Engineer | Minor | A stream's `RESET_ALL_CONTEXTS` could be lost, and framebuffer read errors were swallowed | Fixed: a `reset_pending` flag is cleared only once the reset is sent, and read failures are logged |
| 14 | Senior Engineer | Minor | The level was chosen from frame area only | Fixed: Annex A's per-side limit (√(8·MaxFS)) is also checked, with tests for wide desktops |
| 15 | Senior Engineer | Minor | The NVENC availability probe set up a full encoder | Fixed: it now opens a session and closes it, with no encoder setup or buffers |
| 16 | Ethical Hacker | Minor | Gap between hashing OpenH264 and loading it (time of check vs time of use) | Accepted: changing the file needs write access to the user's own data folder. Recorded in the threat model |
| 17 | Senior Engineer | Note | Intel (iHD) and CBR `slice_qp_delta` are unverified | Still open: a hand check on Intel, recorded in the [charter](../testing/charters/2026-10-25-gpu-h264.md) |

After the fixes, the following were re-run:

- `fmt`, `clippy --all-features`, all tests, `cargo deny` and the layer check;
- the `codec_video` fuzz target (824k runs);
- the AMD GPU tests: unit, `--check-h264` (1080p at 130 frames/s), and the end-to-end script.
