# M9.1 review: Farsight Sharing app, agent badges, logos (2026-10-24)

The change being reviewed fixes user feedback from the first install ([P-50](../decisions/provisional.md)).
It was reviewed by the Senior Engineer and the Security Architect, as
[code-review.md](../process/code-review.md) requires for changes that touch networking defaults and secrets.

| # | Persona | Severity | Finding | Resolution |
|---|---|---|---|---|
| 1 | Both | Major | The settings file also applied to headless desktops, so choosing "Computers on my network" opened them to the LAN as well | Fixed: the settings file is read only for the live desktop (`parse_farsight`), and a test covers it |
| 2 | Both | Major | The password being typed was held in a plain `String` and could appear in `Debug` output | Fixed: the typed password is held in `Zeroizing<String>`, and `Message` has a hand-written `Debug` that hides it |
| 3 | Senior Engineer | Minor | The agent and the app each had their own settings parser, and the two had already drifted apart | Fixed: there is now one parser, `farsight_server::settings` |
| 4 | Senior Engineer | Minor | An unknown value such as `announce = maybe` turned the setting off | Fixed: only yes/no words are accepted, and anything else keeps the default (tested) |
| 5 | Senior Engineer | Minor | Some functions took boolean flag parameters | Fixed: `Sharing::{On, Off}`, and `trust_network` / `untrust_network` |
| 6 | Senior Engineer | Minor | A failed reload was ignored after the password changed | Fixed: the app reports that sharing didn't pick up the new password |
| 7 | Senior Engineer | Minor | `systemctl` and similar calls blocked the UI thread | Fixed: work now runs on `spawn_blocking`, and the window shows "Working…" |
| 8 | Security Architect | Minor | The settings folder and file were created with the umask's permissions | Fixed: the folder is 0700 and the file is 0600, written in one step with a temporary file and a rename (tested) |
| 9 | Security Architect | Minor | Turning on network access through the settings file went unnoticed | Fixed: the agent logs when `listen = lan` comes from the file, and the threat model has a new row for it |
| 10 | Senior Engineer | Nit | `has_login` parses the human-readable output of `farsight-passwd` | Accepted for now; a machine-readable option will come with the next change to `farsight-passwd` |
| 11 | Security Architect | Nit | The username comes from `$USER` | Accepted: this matches the agent's own `owner()`, and the user can change it only for their own session |
