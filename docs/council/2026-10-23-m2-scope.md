# Council: M2 scope amendment (pseudo-encodings needed by the viewer MVP)

Date: 2026-10-23 · Chair: Product Owner · Items: ENC-11 (part), VWR-3
Conducted by Claude adopting each persona in turn, during implementation (the user asked that building continue
without waiting). Logged in [provisional decisions](../decisions/provisional.md) as P-1.

## Proposal: move ExtendedDesktopSize/SetDesktopSize, Cursor and CursorWithAlpha from M8/M9 into M2
**Framing (BA):** Slice 2 "View my existing VNC server". VWR-3 (remote resize) is already in M2, but it can't work
without ExtendedDesktopSize/SetDesktopSize. Without the Cursor pseudo-encodings, a remote pointer drawn into the
framebuffer lags behind the mouse (or appears twice), which breaks the slice's outcome.
AC: resizing the viewer window resizes the remote desktop when the server supports it. The local pointer shows the
remote cursor shape with no visible lag.

**Round 1**
| Persona | Position | Note |
|---|---|---|
| CA | SUPPORT | Decoder-only additions inside `farsight-codec`. No new ports. |
| SE | CONCERN | Keep it small: decode only. Server-side encoders stay in M8. **Accepted.** |
| PO | SUPPORT | Without them, the M2 outcome doesn't really work. |
| QA | CONCERN | Fuzz the cursor decoder, and cover resize in the TigerVNC interop test. **Accepted.** |
| SA | SUPPORT | — |
| UX | SUPPORT | Nielsen #1: the pointer gives immediate feedback. |
| PA | SUPPORT | — |
| EH | CONCERN | Cursor size bombs (API10): cap the cursor at 256×256 and validate mask length. **Accepted.** |
| BA | SUPPORT | — |

**Outcome:** ACCEPTED-WITH-CONDITIONS · moved to **M2** (decode side only). M8 keeps the encoders.
