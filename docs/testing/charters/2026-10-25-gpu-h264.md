# Q3 charter: H.264 on the GPU and DMA-BUF capture (M10)

*Explore* H.264 encoding and DMA-BUF capture *with* real GPUs and desktops *to discover* whether Farsight
can turn them on in release builds (U-14), where they fail, and whether the fallbacks hold.

## Build
On the computer under test, from a checkout of the `m10/gpu` branch (or `main` once merged):

```bash
cargo build --release -p farsight-agent -p farsight-passwd \
  --features farsight-agent/h264,farsight-agent/vaapi,farsight-agent/nvenc,farsight-agent/dmabuf
cargo build --release -p farsight --features farsight/h264
target/release/farsight-agent --install-openh264    # once, for the picture check and the fallback
target/release/farsight --install-openh264          # once, on the viewer computer
```

## Checks
1. **Which encoder:** run `target/release/farsight-agent --check-h264`.
   - Expect `NVENC (NVIDIA)` on the NVIDIA machine and `VA-API (AMD/Intel)` on the AMD one.
   - Expect `Picture check: OK`, and a speed of at least 60 frames per second at 1920×1080.
2. **End to end (X11 or Xvfb):** run `BIN=target/release tests/e2e/agent-h264-gpu.sh`. It should print
   `GPU H.264 end-to-end: OK` and name the GPU.
3. **Real session:** share the desktop with `farsight-agent --h264 --listen lan`, then connect from another
   computer with `farsight -H264 <address>`.
   - Scroll a long web page and play a video: the result should be smooth, with no smearing that lasts past
     the next keyframe (at most 10 s).
   - Text should stay readable when the screen is still.
4. **Resize:** change the agent's screen resolution during a session. The stream restarts with a keyframe
   and the picture stays correct.
5. **Fallbacks:** stop the GPU encoder from loading (for example with `LD_LIBRARY_PATH` pointing to an empty
   folder that shadows `libva-drm.so.2` or `libnvidia-encode.so.1`). The agent should log the fallback and
   either use OpenH264 or send lossless updates. The viewer keeps working either way.
6. **DMA-BUF (Wayland: COSMIC, GNOME, KDE):** run the agent with `RUST_LOG=farsight_capture_wayland=debug`.
   - Sharing works, and the log shows no "cannot map" warnings.
   - If the compositor won't produce linear DMA-BUFs, capture falls back to shared memory without user-visible
     errors.
7. **Many viewers:** connect five viewers with `-H264`. The first four get H.264 (a GPU session each, or
   OpenH264 once the GPU's limit is reached; consumer NVIDIA cards cap concurrent NVENC sessions). The fifth
   gets lossless updates. Every viewer keeps working.
8. **Intel (if one is available):** run checks 1 and 2 on an Intel GPU. The iHD driver must accept Farsight's
   packed headers, and the picture must stay correct under constant bit rate (review note 17).

Record results here, including the GPU, driver version, desktop and Farsight commit. When checks 1–7 pass
on both machines, tell the maintainers whether to enable the features in release builds.
